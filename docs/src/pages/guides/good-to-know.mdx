## Files not committed yet

A file with no commits gets the current time. That is most likely the date it gets when you commit
it.

## Bulk commits count

If one commit touches every file (a reformat, a move to a new folder), every `git Last Modified`
entry gets that commit's date. That is why the keywords are opt-in per entry, not a global switch.

## Moving from `type: 'content'` collections

The `glob()` loader works a little differently from the old collections:

- Entries have an `id` and no `slug`. Use `entry.id` in URLs. A `slug` field in the frontmatter
  still sets the `id`.
- Render with `render(entry)` from `astro:content`, not `entry.render()`.
- `entry.body` can be `undefined` in the types. Use `entry.body ?? ""` where a string is needed.
- Files and folders starting with `_` are no longer skipped for you. Add negated patterns to keep
  that:

```ts
glob({
  pattern: ["**/*.{md,mdx}", "!**/_*", "!**/_*/**"],
  base: "./src/content/blog",
});
```

## Other tools that read your frontmatter

Search indexers, feed scripts and other tools that parse the markdown files themselves see the raw
`git Last Modified` text, not a date. Use the [helpers](/reference/exports) in those tools.

## The dev cache

Astro skips files whose content has not changed since the last run. So in `astro dev`, a date can
stay out of date until the file changes, or until you delete `node_modules/.astro`. CI builds start
clean, so this does not affect deploys.
